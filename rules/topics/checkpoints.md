# Checkpoints and context size

Keywords: checkpoint, context, long chat, growth budget, agContext, compact, heavy turn, fresh session, stale session

Trigger sentence (core): about 20+ turns with heavy tool output, or right after a milestone, the brain writes the baton and hands off to a fresh brain session on the same model itself (otherwise recommend a fresh chat). Claude Code and Codex compact the conversation natively; the baton (`.agents/STATE.md`) carries cross-tool handoff and decision notes carry the why.

- **Size the task first.** A task whose reading won't fit comfortably in one chat: split it, or send the reading to subagents (their reads stay out of the main chat).
- **No native compaction (Antigravity)**: after each finished task run `node ~/.agents/tools/agContext.mjs` (measured prompt size from the chat store vs this project's growth budget) and checkpoint when it prints `checkpoint`. Store unreadable (it says so): checkpoint after 3 heavy turns (a turn that read 300+ lines or got a big tool output).
- **What a checkpoint saves**: the baton, plus a decision note or backlog item only for what this chat holds that git doesn't (a decision, finding or open question). Work committed and pushed with the baton written → nothing more; never duplicate git history.
- **Suggest, never auto-clear**: when a checkpoint is due at a task's end, save first, then suggest a fresh start and let the user act. Never call `clear_session` on your own chat: it wipes history the user still wants to check, and nothing resumes by itself. Claude desktop: propose one fresh session (`start_session`, initiation "own_initiative", context "fresh", a worktree, brief "continue" plus one line on what is next) and end with: "Checkpoint saved. Start the fresh session from the card when you're ready; this chat stays as it is." No such tool (Antigravity, CLI): "Checkpoint saved; open a new chat and type `continue` when you're ready." Never checkpoint mid-step, with unsaved work, or with a question to the user still open.
- **Stale session → new session, not clear**: a chat over a day (24h) old (`CC_WATCH_MAX_AGE_H`) is stale (age only: a "rules changed" check can't tell your own commits from other agents') (session-watch flags it once). A clear keeps the old worktree, branch and loaded skills, so at the next task boundary save first, then open a fresh session yourself (desktop `start_session`, "fresh", worktree, brief "continue") and say this one can be archived. No such tool: "This chat is stale; open a new chat and type `continue`."
